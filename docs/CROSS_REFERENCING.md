# Cross-referencing against FTC / IC3 / BBB — findings and what it would take

Phase 3c asked to cross-check candidates against FTC consumer alerts, FBI IC3 advisories, and BBB Scam Tracker to corroborate entries and attach additional citations — and, if no feed is practical, to document what it would take rather than fake the integration. Researched 2026-09-11 (live web search, sources linked below). **No integration was built.** Here's why, and what a real one would actually require.

## What exists today, per source

**FTC — no public feed for the actual report data.** The Consumer Sentinel Network (the underlying database of consumer fraud reports) is explicitly law-enforcement-only — non-government contributors, including the public, cannot query it. The FTC does publish two real public API endpoints (`ftc.gov/developer`), but they're for Do Not Call complaint counts and HSR merger-notice filings — nothing scam-related. The only public-facing scam content is the human-readable `consumer.ftc.gov/consumer-alerts` blog (what `generate-daily-scam.js`/`generate-gov-scam.js` already find via `web_search`) and an annual/quarterly PDF Data Book, not a feed. ([Consumer Sentinel Network Data Book 2024](https://www.ftc.gov/system/files/ftc_gov/pdf/csn-annual-data-book-2024.pdf), [FTC data & visualizations](https://www.ftc.gov/news-events/data-visualizations))

**FBI IC3 — no public API or RSS for its PSAs.** `ic3.gov/PSA` is a plain HTML listing of press releases, with no feed. (The FBI's separate Cyber Division does maintain an RSS feed at `fbi.gov/investigate/cyber/alerts/<year>/RSS`, but that's general cyber-threat alerts, not consumer-scam PSAs specifically, and isn't guaranteed to exist at a stable URL year to year — it's dated per-year in the path.) ([IC3 Press Releases](https://www.ic3.gov/PSA), [FBI Cyber Alerts RSS example](https://www.fbi.gov/investigate/cyber/alerts/2025/RSS))

**BBB Scam Tracker — no official API at all.** The only programmatic access anyone has is third-party, unofficial scraping services (Apify, ScrapingBee, etc.) built against BBB's own public website with no BBB involvement or endorsement. ([bbb.org/scamtracker](https://www.bbb.org/scamtracker))

## What a real integration would actually require

Given the above, "cross-reference against these three sources" can't mean "call their API" — none of the three offer one for this data. The realistic options, in order of how defensible they are:

1. **Nothing changes for FTC/IC3 today.** Both bots already search these sources' own public pages via `web_search` at generation time (that's what "the general daily researcher" and "the government-source scanner" already do) — this *is* the cross-reference, just not a separate corroboration pass against a structured feed, because no such feed exists to check against.
2. **A scheduled scrape of `ic3.gov/PSA`'s HTML listing** is technically possible (it's a public page, not gated) but fragile — no versioned API, no rate-limit contract, breaks silently the next time the FBI redesigns that page, and the PSA page's own structure would need to be reverse-engineered and re-verified periodically. Same shape of risk for `bbb.org/scamtracker`'s search results, with an added concern: BBB's own Terms of Service should be checked before scraping it at all, even for a non-commercial safety project — this wasn't done here and would be a prerequisite, not an afterthought.
3. **A paid, licensed data feed** is the only version of this that wouldn't be fragile-by-construction. The FTC's Consumer Sentinel is explicitly closed to non-law-enforcement, so that path doesn't exist even with money. IC3 and BBB have no equivalent licensed-feed program that turned up in this research either — this genuinely may not be purchasable at any price today, not just impractical at Scampedia's budget.

**Recommendation: don't build this now.** The two bots already draw on FTC/IC3's own public-facing content through search; a separate "corroboration pass" against the same sources they already read from would mostly re-verify what the citation/relevance gates already check, for a fragile HTML-scraping cost that's disproportionate to what it would add. Revisit only if a real, official feed appears for one of these three — search this doc's three source links again before building anything, since agency data-access policy is exactly the kind of thing that changes without much notice.
